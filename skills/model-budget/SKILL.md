# 预算与批准

调用外部模型是要花钱的。这个插件把"花多少"变成用户能控制的东西，
而不是一个事后才发现的问题。

## 三道闸

用户在 **设置 → Model Cognition → 用量与预算** 里设定，单位都是美元：

| 设置 | 作用 |
| --- | --- |
| **单次上限** `maxCostPerCallUsd` | 任何一次调用的预估超过它，**直接拒绝**，不可批准 |
| **每日上限** `maxCostPerDayUsd` | 今日累计 + 本次预估超过它，**直接拒绝** |
| **自动放行阈值** `autoApproveUnderUsd` | 预估不超过它 → 直接执行；超过 → 需要用户批准 |

区别很重要：

- **单次/每日上限是硬线**。被它拦住的调用**没有批准通道**，也不能靠重试绕过。
  你唯一该做的是把情况告诉用户，让他自己决定要不要提高上限。
- **自动放行阈值是软线**。超过它会生成一条待批准项，用户点一下就能放行。

**未定价的模型**：只有用户在供应商里填过价格的模型才会计价。
没填价格的模型显示"未定价"，**不会被任何一道闸门拦住**（因为无法估算）。
所以"没被拦住"不等于"不花钱"——如果用户在意花费，应该提醒他去补价格。

## 预估是怎么来的

调用发出前，插件按 prompt 的字符粗算输入 token（CJK 字符按 1 token、
拉丁字符按约 4 字符 1 token），加上 `maxTokens` 作为输出上限，再乘用户填的单价。
这是一个**上界性质的粗估**，不是精确值：

- 真实花费以供应商返回的 usage 为准，调用后按实际 token 记账。
- 因此实际花费通常**低于**预估（模型很少用满 `maxTokens`）。

这也意味着：**降低 `maxTokens` 是让调用通过闸门最直接的办法**，
而且不会影响答案质量——除非你确实需要很长的输出。

## 被 pending_approval 拦住时

工具会返回：

```
{
  "status": "pending_approval",
  "approvalId": "ap-m3k2x9-4f1a2b",
  "provider": "anthropic",
  "model": "claude-sonnet-4",
  "estimateUsd": 0.0123,
  "reason": "预估 $0.012300，超过自动放行阈值 $0.005",
  "hint": "…"
}
```

正确的处理顺序：

1. **不要重试**。不带 `approvalId` 的重试只会再生成一条待批准项，把面板弄乱。
2. **把请求完整地呈现给用户**：
   - 要问哪个模型
   - 要问什么（**摘要即可，不必贴全文，但要说清用途**）
   - 预估多少钱
   - `approvalId`
3. **等用户决定**。他说"批准"之后，你**不能替他点**——批准是设置面板里的操作，
   或者他明确告诉你已经批准了。
4. 得到批准后，用**完全相同的 `model` 和 `prompt`**，带上 `approvalId` 重试。

## 批准是严格绑定的

这一点值得单独记住，因为它是设计上故意的：

- **一次性**：用过的批准立刻作废，不能拿它再买第二次调用。
- **绑定内容**：批准记录里存了 provider、model 和 prompt 文本的摘要。
  改了 prompt 里的任何一个字，批准都不再匹配，会重新回到待批准。
- **会过期**：批准后 30 分钟内没有使用就失效。

所以：**先想清楚要问什么，再申请批准**。反复"申请—改主意—重新申请"会让用户很烦，
也会让面板里堆满废记录。

## 查看花费

```
model_usage({ limit: 20 })              // 最近 20 条
model_usage({ onlyFailures: true })     // 只看失败的
```

返回今日花费、累计合计、每次调用的模型与 token 与成本、以及当前的待批准项。

账本记录**失败的调用**（token 记 0、成本记 0，但保留错误信息）。
失败的调用通常不额外计费，但会占用你的时间，值得复盘。

**注意**：如果供应商没有返回 usage，token 是按字符估算的，账本里的数字是近似值。

## 用户想省钱时的建议

按效果从大到小：

1. **换更便宜的模型**：同一个供应商里通常有便宜一个数量级的型号，
   而日常任务（摘要、改写、翻译、简单代码）的质量差别远小于价差。
2. **缩小 `maxTokens`**：它同时是成本上限和闸门输入。
3. **不要做无谓的会审**：`model_panel` 的花费是各模型之和。
   2–3 个模型足够，6 个通常只是浪费。
4. **不要重复问同一个问题**：换措辞重问通常得到同一个答案。
   要重问就带上**新的信息**（新的报错、新的约束）。
5. **补全价格**：未定价会让闸门失效。填上价格，闸门才真的起作用。
6. **调低自动放行阈值**：想对每一笔都过目，就把它设成 0。

## 你绝对不该做的

- 不要为了绕过闸门而改写 prompt、缩小 `maxTokens` 到会截断答案的程度、
  或把一次会审拆成多次单问。
- 不要建议用户把上限设成很大的数字来"省事"。如果确实需要更大额度，
  说明**为什么这件事值得花这个钱**，让用户自己决定。
- 不要在没有用户明确同意的情况下，用别的供应商/模型去回答同一个问题来规避审批。
  换模型省钱是可以的（那是正常的技术选择），**换模型绕审批不行**。
